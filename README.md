## :dart: O guia para alavancar a sua carreira

> Hibernate é o ORM (mapeamento objeto-relacional) mais usado do ecossistema Java: é ele que costuma estar por trás do Spring Data JPA em praticamente toda vaga de back-end Java do mercado brasileiro, de bancos e fintechs a e-commerces e sistemas de governo. Ele existe desde 2001, é a implementação de referência da especificação Jakarta Persistence (JPA) e continua evoluindo — hoje na versão 7, com suporte a Java moderno, repositórios inspirados em Jakarta Data e um módulo reativo (Hibernate Reactive) para quem trabalha com Quarkus ou Vert.x. Este guia reúne roadmap, documentação oficial, cursos, livros, canais, ferramentas, projetos práticos e um capítulo dedicado a usar IA na prática com Hibernate — tudo verificado e organizado para quem já sabe Java (e idealmente JDBC/SQL básico) e quer aprender a mapear, consultar e otimizar persistência de dados de verdade.

## 🗺️ Roadmap

- [roadmap.sh — Java Roadmap](https://roadmap.sh/java) — Pré-requisito: a trilha de Java que sustenta tudo o que vem depois em Hibernate.
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — Onde a persistência de dados (e o Hibernate) se encaixa no panorama geral de back-end.
- [Hibernate ORM — Releases](https://hibernate.org/orm/releases/) — Página oficial com o ciclo de vida de cada versão: qual é a estável, qual está em desenvolvimento e quais têm suporte limitado.
- [Hibernate ORM — Roadmap (GitHub wiki)](https://github.com/hibernate/hibernate-orm/wiki/Roadmap) — Roadmap oficial mantido pelo time do Hibernate com o planejamento das próximas versões.
- [Guia de migração para o Hibernate ORM 7 (documentação oficial)](https://docs.hibernate.org/orm/7.4/migration-guide/migration-guide.html) — Guia oficial para quem já usa uma versão anterior e precisa migrar.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Pré-requisitos** — Java sólido (coleções, generics, streams) e SQL básico (SELECT, JOIN, chaves primária/estrangeira). Sem isso, o Hibernate vira uma "caixa-preta" difícil de debugar.
2. **JDBC e a dor que o ORM resolve** — entenda `Connection`, `Statement`/`PreparedStatement` e por que mapear objeto→tabela manualmente é repetitivo e propenso a erro.
3. **JPA e Hibernate** — a diferença entre a especificação (Jakarta Persistence) e a implementação (Hibernate ORM); `EntityManager`/`Session`, `persistence.xml`/configuração via Spring Boot.
4. **Mapeamento de entidades** — `@Entity`, `@Id`, tipos de geração de chave, `@Column`, embeddables (`@Embeddable`).
5. **Relacionamentos** — `@OneToMany`, `@ManyToOne`, `@ManyToMany`, `@OneToOne`, `fetch` (LAZY vs. EAGER) e `cascade`.
6. **Consultas** — HQL/JPQL, Criteria API, Native Queries e (no Hibernate 6+) a nova Criteria tipada.
7. **Transações e concorrência** — `@Transactional`, isolamento, locking otimista (`@Version`) e pessimista.
8. **Performance** — o problema N+1, first e second-level cache, `fetch join`, paginação e o `Hibernate_User_Guide` sobre tuning.
9. **Extensões do ecossistema** — Hibernate Validator (Bean Validation), Hibernate Envers (auditoria), Hibernate Search (busca full-text) e Hibernate Reactive.
10. **Uso em produção** — Hibernate por baixo do Spring Data JPA, do Quarkus ou do Micronaut Data; migrações de schema com Flyway/Liquibase.

**Por onde começar:**

1. **Garanta a base:** um [JDK LTS atual](https://adoptium.net/) (17, 21 ou mais recente), Maven ou Gradle, e uma IDE como o [IntelliJ IDEA](https://www.jetbrains.com/idea/).
2. **Leia a introdução oficial**, que já mostra um exemplo completo: [Hibernate ORM — Introduction Guide](https://docs.hibernate.org/orm/7.4/introduction/html_single/).
3. **Siga o Quickstart oficial** e rode seu primeiro `@Entity` salvando e lendo do banco: [Hibernate ORM — Quickstart](https://docs.hibernate.org/orm/7.4/quickstart/html_single/).
4. **Use um banco em memória para praticar sem instalar nada:** o [H2 Database](https://www.h2database.com/html/main.html) roda embutido no seu projeto.
5. **Aprenda mapeamento e relacionamentos** com um curso completo em vídeo — veja as opções em [🔤 Sites e cursos](#-sites-e-cursos-para-aprender-hibernate) — e o [Hibernate ORM — User Guide](https://docs.hibernate.org/orm/7.4/userguide/html_single/Hibernate_User_Guide.html) como referência.
6. **Entenda o problema N+1** antes de ir para produção: leia [Vlad Mihalcea](https://vladmihalcea.com/) e teste você mesmo habilitando o log de SQL.
7. **Pratique com o Spring Data JPA**, a forma mais comum de usar Hibernate no mercado: [Spring Data JPA — Reference Documentation](https://docs.spring.io/spring-data/jpa/reference/index.html).
8. **Publique um projeto no GitHub** com testes usando [Testcontainers](https://testcontainers.com/) contra um banco de verdade (PostgreSQL/MySQL), não só o H2.

## 🛠️ Ferramentas

> IDE e produtividade

- [IntelliJ IDEA](https://www.jetbrains.com/idea/) — A IDE mais usada por desenvolvedores Java/Hibernate; a edição Community é gratuita.
- [JPA Buddy](https://jpa-buddy.com/) — Plugin de IntelliJ dedicado especificamente a JPA/Hibernate: gera entidades, migrações e valida mapeamentos.
- [JetBrains — Persistence Tool Window](https://www.jetbrains.com/help/idea/persistence-tool-window.html) — Documentação oficial da ferramenta do IntelliJ para visualizar o diagrama de entidades JPA/Hibernate.
- [Visual Studio Code — Java](https://code.visualstudio.com/docs/languages/java) — Guia oficial para programar em Java (e Hibernate) no VS Code com extensões.
- [Eclipse IDE](https://www.eclipse.org/downloads/) — IDE open source tradicional, também usada em projetos Hibernate no mercado.

> Build e ambiente

- [Apache Maven](https://maven.apache.org/) — Ferramenta de build e gerenciamento de dependências mais usada em projetos Java/Hibernate.
- [Gradle](https://gradle.org/) — Alternativa moderna ao Maven, mais rápida em builds incrementais.
- [Docker](https://www.docker.com/) — Empacote sua aplicação e suba um banco de dados real para testar seu mapeamento Hibernate.
- [Spring Initializr](https://start.spring.io/) — Gerador oficial de projetos Spring Boot já com Spring Data JPA (Hibernate) como dependência.

> Banco de dados e testes

- [H2 Database](https://www.h2database.com/html/main.html) — Banco de dados em memória, ótimo para praticar mapeamentos Hibernate sem instalar nada.
- [Testcontainers](https://testcontainers.com/) — Sobe um banco de dados real (PostgreSQL, MySQL etc.) em container Docker durante os testes de integração.
- [DBeaver](https://dbeaver.io/) — Cliente de banco de dados gratuito e multiplataforma para inspecionar o SQL que o Hibernate gera.
- [DataGrip](https://www.jetbrains.com/datagrip/) — IDE de banco de dados da JetBrains, integra-se bem ao fluxo de quem já usa IntelliJ.
- [Flyway](https://www.red-gate.com/products/flyway/community/) — Controle de versão e migração de schema de banco de dados, com starter oficial no Spring Boot.
- [Liquibase](https://www.liquibase.com/community) — Alternativa ao Flyway para versionamento de banco de dados.
- [p6spy](https://github.com/p6spy/p6spy) — Intercepta e loga o SQL real gerado pelo Hibernate, essencial para debugar performance.

> Produtividade e utilitários específicos do Hibernate

- [Lombok](https://projectlombok.org/) — Gera getters, setters, construtores e builders via anotações, reduzindo boilerplate nas entidades.
- [MapStruct](https://mapstruct.org/) — Gera código de conversão entre DTOs e entidades Hibernate em tempo de compilação.

## 🤖 IA na prática

Hibernate é um dos temas em que a IA generativa mais erra por excesso de confiança: HQL/JPQL parecem SQL, mas têm regras próprias, e cada versão do Hibernate muda pequenos detalhes de anotações e comportamento padrão (como `fetch` implícito). Usar IA aqui exige mais ceticismo do que em outras áreas.

**Para aprender**
- Peça para uma IA **explicar uma exception clássica do Hibernate** (`LazyInitializationException`, `org.hibernate.exception.ConstraintViolationException`, `StaleObjectStateException`) linha a linha, com a causa mais provável, antes de aplicar a primeira correção sugerida.
- Cole um mapeamento de entidade (`@Entity`, `@OneToMany`, `@ManyToOne`) e peça para a IA **explicar o que cada anotação faz** e qual SQL ela deveria gerar — depois confira habilitando `hibernate.show_sql`/`format_sql` de verdade.
- Peça para **gerar um exemplo mínimo** de um relacionamento específico (ex.: `@ManyToMany` com tabela associativa customizada) e depois pergunte "o que pode dar errado em produção com esse mapeamento?".
- Peça exercícios com gabarito sobre o assunto que estiver estudando (fetch types, cascade, HQL vs. Criteria API).

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), o [JetBrains AI Assistant](https://www.jetbrains.com/ai/) (integrado ao IntelliJ) ou o [Claude Code](https://code.claude.com/docs/en/overview) para gerar entidades, repositórios, DTOs/mappers e testes com Testcontainers — sempre revisando o SQL que o mapeamento vai gerar.
- Use a IA para **detectar o problema N+1**: cole um trecho de log de SQL repetitivo e peça para identificar qual `fetch` ou `join fetch` resolveria.
- Complementar (não é IA generativa, mas resolve um problema parecido): rode o [Hypersistence Optimizer](https://github.com/vladmihalcea/hypersistence-optimizer) no seu projeto — ele analisa a configuração Hibernate real e aponta anti-padrões automaticamente, sem depender de um modelo de linguagem.
- Depois de aceitar qualquer sugestão de código, rode os testes (`mvn test`/`gradle test`) com um banco real via [Testcontainers](https://testcontainers.com/) — muita sugestão de IA funciona no H2 em memória e quebra num Postgres/MySQL de verdade.

**Limites e boas práticas**
- IA confunde a sintaxe de **HQL/JPQL com SQL puro** e inventa nomes de métodos que não existem na API do Hibernate, principalmente entre versões (5→6→7, `javax`→`jakarta`). Confirme sempre no [Hibernate ORM — User Guide](https://docs.hibernate.org/orm/7.4/userguide/html_single/Hibernate_User_Guide.html).
- Ela raramente avisa sobre o **problema N+1** ou sobre `fetch = EAGER` mal usado — são erros de performance que só aparecem sob carga, não em um exemplo isolado.
- Não cole credenciais, strings de conexão de produção ou dados de clientes em ferramentas de IA sem a política de segurança da sua empresa.
- Entenda o que você aceita: em entrevista técnica e em produção, o SQL gerado — e os bugs de performance — são seus.
